# disclosure_date（预约披露日期）Phase 0 PIT 审计

> 2026-09-18 · 结论：**不合格 ⇒ 放弃（作为"事前"特征）** · 探测脚本 `temp/disclosure_pit_probe_20260918.py`（一次性，已删）
> 日志 `logs/disclosure_probe_20260918.log`（临时） · 路线图登记见 `/memories/repo/lazybull_data_layer_roadmap.md`

## 1. 背景与预登记的放弃条件

数据层第 3 个候选（接在 stk_holdertrade / repurchase 之后）。用途设想：**财报窗口回避（风险预判）**。
预登记的风险（2026-09-14 路线图）：

> 预约日期会被变更，**若 TuShare 只给"当前值"则历史不可回溯 → 不合格就放弃**；
> 替代方案：用法定披露截止日（4/30、8/31、10/31）近似，零新增数据。

本次探测就是为了判定该条件。

## 2. 接口实测（3 个报告期 + 1 个未来期，共 4 次调用）

| 项 | 实测 |
|---|---|
| 接口 / 查询方式 | `disclosure_date`，按 `end_date`（报告期）查询，分页读满 |
| 返回列 | `ts_code / ann_date / end_date / pre_date / actual_date`（**无 `modify_date` / 无版本字段**） |
| 行数 | 20231231：5,374；20240630：5,378；20250630：5,437（≈全市场 1 行/股票） |
| **行粒度** | **`(ts_code, end_date)` 重复行 = 0** ⇒ 每个报告期**只有 1 行**（"当前值"），**无历史版本** |
| `ann_date` | 缺失 0%，首播公告日（20231231 期：20231228 ~ 20240427） |
| `pre_date` | 缺失 0%，预约披露日（20231231 期：20240127 ~ 20240430） |
| `actual_date` | 缺失 0.17%~0.45%（未披露/未回填），实际披露日 |
| 未来期 | `end_date=20261231` 返回 **0 行** ⇒ 计划要临近年末才生成，无法"提前一年"拿到 |

## 3. 判别证据：`pre_date` 是否被改写为最终值

| 报告期 | n | `pre == actual` | 推迟 | 提前 |
|---|---|---|---|---|
| 20231231 | 5,374 | **99.7%** | 0.1% | 0.2% |
| 20240630 | 5,378 | **99.9%** | 0.0% | 0.1% |
| 20250630 | 5,437 | **99.8%** | 0.0% | 0.2% |

**解读**：A 股实际"预约日 ≠ 实际披露日"的比例远高于 0.1%~0.3%（变更预约是常见操作，延期披露每年都有
可观家数）。99.8% 的 `pre == actual` 只能解释为：**`pre_date` 已被改写为最终实际披露日**——
即接口给的是"当前值"，不是"当时值"。

⇒ 用它在 T 日构造"已知的预约披露日"必然混入**未来信息**（实际披露日之后回填的值会泄漏到事前窗口），
且**无法用该接口自身还原历史时点值**（没有版本行、没有变更日）。

## 4. 结论

**Phase 0 判定：不合格**（触发预登记放弃条件）——不进入 Phase 1（不新增 raw 数据集、不接因子）。

`actual_date` 本身是**不可逆事实**（PIT 安全：仅当 `T ≥ actual_date` 时可使用），
但"距最近一次实际披露的天数"与既有 `fundamental_freshness_days` / express / forecast freshness 高度重叠，
**不足以单独支撑一个新数据集**。

## 5. 替代路径（零新增数据，待决策）

**披露及时性 / 披露压力**，完全不依赖 `disclosure_date`：

| 候选特征 | 口径 | PIT 安全性 |
|---|---|---|
| `disclose_pressure`（披露压力） | 法定截止日（年报/一季报 4/30、中报 8/31、三季报 10/31）临近而**尚未披露**的状态 | ✅ 截止日是日历规则、"是否已披露"取自已发生的 `ann_date`/`f_ann_date` |
| `disclose_lead_days`（提前天数） | `法定截止日 − 实际披露日`（提前披露 = 正面信号） | ✅ 仅披露后可知 |
| `disclose_delay_flag`（逾期披露） | 实际披露日 > 法定截止日 ⇒ 风险标记 | ✅ 同上 |

**启动条件（预登记）**：必须先证明增量信息——控制既有 `express` / `forecast` / `fundamental_freshness_days`
后的**偏 IC** 显著（t 量级参考本仓先例：|t| ≥ 3 才值得进体检），否则只作登记、不开工。
**风险**：与前三个家族同一教训——"信息存在"不等于"能过净值判据"；本族的原始数据（披露日期）
本质上已部分被 forecast/express 覆盖。
