> 日期：2026-09-17　版本：v0.124.0（数据层第 2 项，接在 stk_holdertrade 之后）
> 路线图：`CLAUDE.md`（holdertrade → **repurchase** → disclosure_date）

> 审计日志：`logs/repurchase_audit_20260917.log`

## 1. 接口与字段

`repurchase`（股票回购，按**公告日** `ann_date` 组织）——9 个字段：

| 字段 | 含义 | 缺失率（2022 全年 6,034 行） |
|---|---|---|
| `ts_code` | 股票代码 | 0% |
| `ann_date` | **公告日期（唯一 PIT 锚点）** | **0%（且 100% 合法）** |
| `end_date` | 进度报告期/截止日 | 33.65% |
| `proc` | **回购阶段**：预案 / 股东大会通过 / 实施 / 完成 / 停止 | 0% |
| `exp_date` | 到期日 | **92.45%** |
| `vol` | 回购数量 | 33.65%（与 `end_date` 同步缺失） |
| `amount` | 回购金额（元） | 5.65% |
| `high_limit` / `low_limit` | 回购价格上限/下限 | 10.85% / 40.55% |

样例（2024-01-31）：
`002385.SZ  20240131  NaN  预案  20250219  NaN  100000000.0  8.32  NaN`

⚠️ **无 `begin_date`**；`end_date` 是进度报告期而非公告期间。**PIT 锚点只能是 `ann_date`**。

## 2. 分页契约验证（v0.123.0 要求，全部实测）

| 项 | 实测结果 | 结论 |
|---|---|---|
| 单页上限 | 不传 `limit` → **2000 行（静默截断）**；`limit=3000/5000` → 仍 2000 | **单页 2000，超限不报错** ⇒ 必须分页 |
| `offset` 语义 | `limit=2000, offset=0/2000/4000…` 逐页取，第 4 页 34 行自然终止 | **支持且能取全** |
| 跨页重复 | 分页拼接内整行重复 **19 行（0.31%）** | 分页后必须**全字段去重** |
| **完整性断言** | 2022 全年：分页合计 **6,034 行** == 逐月独立拉取合计 **6,034 行**，按全字段排序后**逐行 0 差异** | ✅ 硬证据（"小窗口独立拉取"对照通过） |

> 对照：2022 全年真实 6,034 行，若不翻页只会拿到 2,000 行（**丢掉 67%**）。

## 3. PIT 严格性

- **窄窗 vs 宽窗切片逐值一致（0 差异）**：2023-04 单月拉取（637 行）与 2023H1 宽窗按日切片的同一批行完全一致 ⇒ 无"当前值快照"式字段。
- **历史回溯**：2018-01（127 行）、2021-01（458 行）、2024-01（877 行）均可拉；单股全历史（600519.SH）21 行、覆盖 2024-09~2026-05。
- **幂等性**：同窗口连续两次调用逐值一致（398/398）。
- ⚠️ **残留风险**：接口无版本字段（无 `f_ann_date`/`update_flag`），若 TuShare 事后**回填同一 `ann_date` 行的字段**（如预案行的 `vol/amount` 后来补齐），单次拉取无法识别该修订 ⇒ 沿 holdertrade 做法：水位续传时**回拉 3 天重叠窗口**、以最新拉取为准；并在数据集契约里登记该风险。

## 4. 唯一键与聚合口径

| 键 | 重复率 |
|---|---|
| 全字段整行重复 | **0.30%**（6/2000 样本；分页拼接另有 0.31%） |
| `ts_code + ann_date` | **2.70%** |
| `ts_code + ann_date + proc` | 2.40% |
| `ts_code + ann_date + end_date` | 2.10% |

⇒ **无自然唯一键**：去重口径 = **全字段完全相同视为同一行**；`(ts_code, ann_date, proc)` 的**多行明细必须保留**
（不同阶段/多次进度披露是不同事件），聚合在因子层做（沿用 holdertrade 模式）。

## 5. 稀疏度与规模（分区决策输入）

- 2022 全年：**每日行数中位 16**（最大 110），**每日股票数中位 16**（最大 108）；覆盖 **101/243 交易日（41%）**。
- 全年行数 6k（2022）量级，2024 更多 ⇒ **按 `ann_date` 年分区**（沿 dividend / stk_holdertrade 模式：
  年文件 <2 MB、当前年度续传只动 1 个分区、与既有分区语义一致）。
- 比 holdertrade 更稀疏 ⇒ 因子必须**窗口聚合 + 窗口外显式填 0**（否则被训练入口 0.6 缺失率门禁整体删除）。

### 5.1 存储布局（**方案阶段已定，实现验收项**）

> 项目契约（v0.124.0 起）：**新增数据集的 raw 存储布局必须在方案阶段写定并登记**，实现不得自行决定。

| 项 | 决定 |
|---|---|
| 分区维度 / 粒度 | **按 `ann_date` 年分区**：`data/raw/repurchase/YYYY-12-31.parquet` |
| 文件名约定 | `<年末日期>.parquet`（如 `2024-12-31.parquet`），与 dividend / stk_holdertrade 一致 |
| 水位字段 | 分区内 **max(`ann_date`)** |
| 增量回拉窗口 | 水位前回拉 **3 天**（`REPURCHASE_RESUME_OVERLAP_DAYS = 3`，防同日补录/更正） |
| 去重口径 | **全字段完全相同视为同一行**（无自然键；跨页重复 0.31%、源内重复 0.30%） |
| 非法数据处理 | 缺失/非法 `ann_date` 剔除并告警（**禁止伪年分区**） |
| 单页 | `page_limit = 2000` + `offset` 翻页读到空（超限静默） |
| 预估体量 | 每年 6k~15k 行，年文件 < 2 MB |

## 6. 因子草案（历史候选登记；**最终口径见 §6.1**）

| 候选因子 | 口径要点 |
|---|---|
| `rp_active_flag` / `rp_stage_rank` | 当前处于哪一阶段（预案 < 股东大会通过 < 实施 < 完成）；"停止"为负向 |
| `rp_amount_to_mv_90d/180d` | 近 90/180 日**公告回购金额 / 流通市值**（金额缺失可用 `vol × high_limit` 兜底，需登记口径） |
| `rp_price_headroom` | `high_limit / close - 1`（回购价上限相对现价的"托底空间"） |
| `rp_progress_pace` | 已完成金额/预案金额（**需版本化状态机**：同一回购计划跨多期公告） |
| `rp_freshness_days` | 距最近公告自然日数（设计性缺失，同 holdertrade） |

**注意**：`proc` 是状态字段、且同一计划跨多期公告 ⇒ 若要"进度/完成率"类因子，必须做**计划级版本化**
（沿 cashflow v3 的事件版本模式，以 `(ts_code, exp_date/end_date)` 近似计划身份），否则会跨计划混算。
本轮优先做**低风险口径**：公告级窗口聚合（金额/市值、阶段状态、上限空间）+ 哨兵列。

### 6.1 Phase 2 因子口径（**定稿，2026-09-18** —— 实现必须与本节一致；不一致先改本节再改代码）

**列集：4 个值列 + 1 个新鲜度列 + 1 个哨兵列（最小集一次到位，不做 full/core 拆分）**

| 列名 | 口径 | 缺失/兜底 |
|---|---|---|
| `rp_amount_to_mv_90d` | **执行类公告增量金额**：`Σ 增量(元)` over 自然日开区间 `(T−90, T]` ÷ 流通市值(元) | `amount` 缺失**不兜底**，增量记 0 并计数告警；`circ_mv` 不可得 → 0 |
| `rp_amount_to_mv_180d` | 同上，窗口 `(T−180, T]` | 同上 |
| `rp_exec_flag_90d` | 90 日内是否出现 `proc ∈ {实施, 完成}` 公告（0/1） | 窗口内无公告 → 0 |
| `rp_price_headroom` | 窗口 `(T−180, T]` 内**最新一条**带 `high_limit` 的公告：`high_limit ÷ VWAP(T) − 1` | 窗口内无有效 `high_limit`、或当日 `VWAP` 不可得 → 0 |
| `rp_freshness_days` | `T − max(ann_date ≤ T)`（自然日） | 无历史公告 → NaN（设计性缺失，同 holdertrade） |
| `repurchase_schema_v1` | 哨兵列，对当日全截面恒写当前版本 `1`（含无事件股票） | — |

**关键口径登记（逐条为验收项）**

1. **窗口一律自然日开区间 `(T−W, T]`**，PIT 锚点只有 `ann_date`——raw 无 `begin_date`，
   `end_date` 是进度报告期（缺失 37.3%）而非"发生日"，不得当可用时间用。
2. **金额缺失不兜底（用户决策，2026-09-18）**：`amount` 缺失 5.7%，**不用** `vol × high_limit` 近似——
   两种口径混进同一列会让"回购强度"跨股票不可比。缺失行按 0 计入当日合计并计数告警；
   **硬门禁**：`amount` 整列缺失或全空 → 直接报错（禁止静默零因子）。
3. **VWAP 口径**：`VWAP(T) = amount(千元) × 10 ÷ vol(手)`（元/股；实测与未复权 `close` 中位相对偏差 0.7%，
   量纲为 TuShare 原生单位，cleaner 未改写；停牌日 `vol = 0` ⇒ 不可得）。
   选 VWAP 而不是 `close`：**cs_train 不含未复权 `close`**（`amount`/`vol` 在），
   避免为 1 列因子在训练/OOS 评估/OOS 回测/纸面四侧再管道一张价格表。
   `amount` 或 `vol` 列缺失 → 报错（schema 漂移不得静默降级）。
4. **事件聚合（同 `(ts_code, ann_date)` 多行）**：`amount` **求和**、`exec` **取 max**、
   `high_limit` 取该日**非空最大值**（源数据无自然键，`ts_code+ann_date` 重复 4.78%——
   沿 stk_holdertrade 教训，禁止按行计数把重复披露放大成"多笔"）。
   `proc` 取值域固定 5 值（预案/股东大会通过/实施/完成/停止）；未登记取值 → 忽略阶段语义、仅计金额并告警。
4.1 **`amount` 是"累计"还是"计划"？——实测结论（2026-09-18，实现期发现，必须先改方案）**：

   **执行类行（实施/完成）的 `amount` 是"累计已回购金额"**，不是该期增量。证据（全库 63,639 行）：
   同一股票同一 `proc` 连续公告的**金额中位"末/首"比**：完成 **12.5**（3,144 组）、实施 **12.6**（277 组）、
   停止 17.7；且 **23.6%** 的组金额**完全单调非降**（例：`600382.SH` 2024 年逐月 `完成` 行
   2.52e8→2.74e8→2.84e8→…→3.29e8，逐月递进）。⇒ **禁止在窗口内直接求和**：
   会把同一笔回购重复计 10 倍以上（实测 H1 2024 该股窗口求和 2.4e9 元 ≈ 流通市值的 34 倍）。

   **增量口径（登记为定稿）**：对同一股票的执行类行按 `ann_date` 升序（**次级键 `end_date`**：进度报告期；
   `end_date` 缺失的排最后），`增量 = 本行金额 − 上一有效执行类行金额`；若本行金额更小（新计划开始/数据修正）
   或为首行 ⇒ 视为新计划，`增量 = 本行金额`；`amount` 为 NaN ⇒ 增量 0 且**不更新基线**（缺失不兜底）。
   **次级键是必需项**：同日多行若按文件行序处理，遇到 `end_date` 与行序不一致的两行
   （实测 `300138.SZ` 20240604 同时报 20240531 / 20240603 两期）会把"回落"误判为新计划、
   虚增一整笔累计金额；按 `end_date` 排序后该股当期增量为 0.592e8（= 0.395e8 + 0.198e8）✓。
   增量按**公告日**归属：窗口 `(T−W, T]` 内的增量之和 = 窗口内披露的回购进展金额
   （跨窗口起点的那一笔增量整笔计入其公告日所在窗口，属登记在案的近似，
   实测 `600382.SH` 2024H1 窗口 135.1e6 = 区间累计差 110.0e6 + 首行增量 25.1e6 ✓）。

   **非执行类行（预案/股东大会通过）的 `amount` 是"计划金额"，且同一计划会被重复披露**
   （实测 股东大会通过 组末首比中位 **1.04** ⇒ 同一数值跨期重复）⇒ **不得进入强度列**
   （与"已执行金额"不同量纲、且会重复计）。它们只贡献 `high_limit`（价格上限）与 `rp_freshness_days`。
   **已知代价（登记在案）**：仅发预案、尚未执行的公司强度列为 0（"只说不做"不可区分于"未公告"），
   该维度由 `rp_exec_flag_90d` 与 `rp_price_headroom` 部分承载。
5. **不做计划级版本化（本轮明确延后）**：进度/完成率类因子需要 `(ts_code, exp_date/end_date)` 近似计划
   身份 + 同位计划版本键，另立方案。**已知代价（登记在案）**：`停止`（全库 31 行，0.05%）不参与状态语义，
   其金额仍计入强度 ⇒ 极少数"已终止计划"会被当作正向强度，本族已知偏差。
6. **不做公共事件衰减**：滚动窗口滑动本身即时间衰减（同 stk_holdertrade 契约），本族默认不进事件衰减登记。
7. **0 填充语义**：查询表**只输出「180 自然日内有公告」的股票**（控内存），其余由 handler **显式填 0**
   （语义 = 窗口内无回购计划），保证 4 列全市场覆盖，**不得**被训练入口 0.6 缺失率门禁整体删除。
   **已知混同（登记在案）**：`rp_price_headroom = 0` 同时表示"窗口内无公告"与"有公告但无有效价格上限"
   （`high_limit` 缺失 11.4%）。
8. **接线 = 运行时派生**（同 stk_holdertrade 先例）：训练 / OOS 评估 / OOS 回测 / 纸面四侧派生，
   **不写回 cs_train / cs_infer**；查询表由调用方一次性构建（全折共用）。
9. **采纳判据**：先过信号层尺子（`scripts/compare_wf_signal_metrics.py`，噪声带 ±10 bps / ±0.6pp，
   相对降幅 ≥9% 才值得）再决定是否跑全量净值 A/B（主判据 ΔMaxDD）。

## 7. 结论

**PIT 合格 → 可进 Phase 1**（薄接入、默认关、可回退）。Phase 1 硬约束：

1. **单页 2000 + offset 翻页读到空**（`_query_with_pagination(page_limit=2000)`；触顶页继续翻、`max_pages` 兜底告警）；
2. **分页后全字段去重**（跨页重复实测 0.31%）；
3. **无自然键**：`(ts_code, ann_date, proc)` 多行保留、聚合在因子层；
4. **PIT 锚点 = `ann_date`**；水位 = 分区内最大 `ann_date`，增量回拉 3 天；非法/缺失 `ann_date` 剔除并告警；
5. 按 `ann_date` **年分区**落盘（`data/raw/repurchase/YYYY-12-31.parquet`）。
