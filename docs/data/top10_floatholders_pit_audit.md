## 3. PIT 严格性

| 项 | 实测 | 结论 |
|---|---|---|
| `ann_date` 完整性 | 缺失/非法 **0%** | ✅ 可作为唯一 PIT 锚点 |
| 同期多版本 | `(ts_code, end_date)` 有 >1 个 `ann_date` 的比例：20231231 期 **1/5,559（0.02%）**、20240630 期 **0/5,575（0%）** | ✅ **无需版本状态机**；按 `ann_date ≤ T` 过滤即可（极少数多版本会被保守地延后可见） |
| `ann_date` 参数语义 | `ann_date=20240426` → 17,347 行（跨多个报告期：end_date 20240331~20240422） | 可用于按公告日拉取，但**粒度不是我们需要的**（一次公告跨报告期） |
| `start_date/end_date` 参数 | `start=end=20231231` 与 `period=20231231` 返回**同一报告期**但页内构成不同；`start=20240420,end=20240430` 返回 530 行且 `ann_date` 跨 20240425~20240515 | ⚠️ 语义不透明（疑似按报告期过滤）⇒ **Phase 1 禁止使用 start/end**，增量一律按 `period` |
| 公告节奏 | 单期 `ann_date` 唯一值 38~57 个（即同一报告期在 1~2 个月内陆续披露） | 特征侧需"状态保留 + freshness"，不能按日快照 |

**PIT 判定：合格**。T 日截面 = 取 `ann_date ≤ T` 的最新一个已披露报告期的全部股东行。

## 4. 唯一键与聚合口径

| 键 | 重复行数（period=20231231，54,890 行） |
|---|---|
| 全字段整行重复 | **0** |
| `(ts_code, end_date)` | 49,331（正常：每股 10 行） |
| `(ts_code, end_date, holder_name)` | 2 |
| **`(ts_code, end_date, ann_date, holder_name)`** | **0**（该样本期；全历史 0.06%，见下） |
| `(ts_code, end_date, ann_date, hold_amount)` | 652 |

- ⇒ **唯一键 = `(ts_code, end_date, ann_date, holder_name)`**。
- 行数分布：`=10` 占 96.0%、`<10` 占 ~3.0%（新股 / 股东不足 10 户）、`>10` 占 ~1.0%
  （名称唯一但行数超 10，属源侧口径细节）。
- **⚠️ 全历史修正（Phase 1 落盘验收实测，2026-09-18，已修正上述“重复 0”的样本结论）**：
  全库 2,887,432 行中，唯一键**非零重复**：**861 组 / 1,731 行 / 占比 0.06%**（组大小：2 行 852 组、3 行 9 组），
  逐年自 2013–2016 最多（143~227 行/年）。所有重复组都是**同一 `ann_date` 下同名持有人出现两行不同金额**
  （例：`000001.SZ` 20110818 海通证券 47,886,357 / 49,305,821；`000011.SZ` 20260829 深圳市投资控股
  301,411,311 / 303,411,311）——疑为**同一公告的修订版与初版并存**；加 `hold_amount` 后全库重复 **0**。
  **⇒ Phase 2 聚合口径必须登记**：同 `(ts_code, end_date, ann_date, holder_name)` 多行时
  **取 `hold_amount` 最大的一行**（代表该持有人的最终持股），**禁止求和**（会把同一笔持仓重复计）；
  不得回退为“按行数取前 N”（会把同一人当成两个名次）。
- **分析口径约定**：先按上述规则对同名多行去重（取 `hold_amount` 最大行），再取该版本全部行、按 `hold_amount` 降序取前 N（N=10 或全量），
  **禁止**假设"恰好 10 行"或"行数即名次"。

## 6. 因子口径定稿（Phase 2 实施依据，2026-09-18 实测后再定）

### 6.1 列集（6 值列 + freshness + 哨兵）

| 列 | 口径 | 实测依据 |
|---|---|---|
| `tfh_top10_ratio` | 前 10 大流通股东**合计占流通比**（`hold_float_ratio` 求和，%） | 组级分位 [3.5, 28.1, **43.3**, 58.4, 89.6]，无堆积 |
| `tfh_top1_ratio` | **第一大**（金额最大行）占流通比（%） | 集中度主轴备份 |
| `tfh_inst_ratio` | **长线机构**合计占流通比（白名单见 6.2） | 正交轴核心（`fund_portfolio` 看不到社保/养老/年金/保险） |
| `tfh_inst_count` | 长线机构**户数**（0~10） | 同上，序数强度 |
| `tfh_social_security_flag` | 前 10 中出现社保类持有人（0/1） | 长线资金信号（社保行占比 1.71%） |
| `tfh_concentration_chg` | `tfh_top10_ratio` − **上一已存报告期**同口径值（百分点） | 97.7% 组可算；不用源侧 `hold_change`（缺失 22–55%） |
| `tfh_freshness_days` | T − 该报告期 `ann_date`（**自然日**） | 中位 62–70 天，p99 > 2,000（极少数长期停牌/退市） |
| `tfh_schema_v1` | 哨兵（当前值 1） | 沿既有契约 |

**不纳入本轮**（登记、日后可加，需重新预登记）：基金类（开放式/封闭式投资基金、基金专户理财）
与 `fund_portfolio` 家族重叠；资管公司/券商/信托/财务公司/国资局等久期与法律性质庞杂。

### 6.2 长线机构归类（`holder_type` 白名单，实测 38 类）

白名单（6 类，合计 **4.66%** 行占比）：`社保基金、社保机构`（1.71%）、`基本养老保险基金`（0.19%）、
`企业年金`（0.15%）、`保险投资组合`（2.28%）、`保险资管产品`（0.09%）、`金融机构—保险公司`（0.24%）。
匹配用**规范化后的整串相等**（先按中文标点与空白归一），**禁止模糊子串匹配**
（否则 `金融机构—证券公司`、`公益基金`、`职工工会` 等会被误纳）。

### 6.3 聚合口径

1. 同 `(ts_code, end_date, ann_date, holder_name)` 多行（全库 0.06%）⇒ **取 `hold_amount` 最大行**（§4）；
2. 组内按 `hold_amount` 降序取前 **10** 行（>10 行的组占 1.0%）后再求和/取首；
3. `hold_float_ratio` 组级缺失 **6.99%**（2007 年 6.2% → 2023 年 1.1%）⇒ **缺失行按 0 贡献跳过求和**
   （不用 `hold_ratio` 冒充、不整组置 NaN）；**已知代价**：缺失行所在组会**低估**集中度
   （登记为口径代价，Phase 3 用缺失率剖面复核）；
4. `tfh_concentration_chg` 的"上一期"= 该股票**按 `end_ord` 排序的上一条已存报告期**
   （允许跳季/跳年，不做日历补齐）；首期 ⇒ NaN；
5. PIT：T 日可见 = `ann_ord ≤ T` 的**最新一次披露**（同 `ann_ord` 多行取 `end_ord` 最大）；
   **状态保留 + freshness**（沿 consensus 契约，禁止硬断崖）——**已知代价**：极少数长期停牌/退市股票
   携带极旧报告，由 `tfh_freshness_days` 显式暴露，本轮不做截断。

### 6.4 填充语义（与 holdertrade/repurchase **不同**，必须按本族语义）

- **有已披露报告**的股票 ⇒ 值列为真实值（**0 = 前 10 中无此类持有人**，是有效观测）；
- **无任何已披露报告**（新股尚未披露）⇒ 6 个值列与 freshness **全 NaN**（语义 = 未披露）；
  哨兵列**仍写当前版本**（覆盖全市场，供训练入口校验）。
- **禁止对未披露股票填 0**——本族 0 是"无此类持有人"，混用会制造假信号（与事件族语义相反）。
- 覆盖实测：存活股票几乎 100% 有已披露报告（2015/2020/2025 抽样日均 ≥ 当日 raw daily 股票数），
  因此 NaN 占比极低，不会被训练入口 0.6 缺失率门禁整体删除。

### 6.5 运行时容器（**偏离既有 `{trade_date: DataFrame}` 模式，原因登记**）

本族**逐日全市场稠密**（~5,500 只/日）⇒ 若沿 repurchase 的逐日字典，3,500 个交易日将膨胀到
~1,900 万行 / GB 级内存。因此：

- `build_top10fh_panel(df)` → **面板**（每股每报告期一行，全历史 ~27 万行，含 `ann_ord`）；
- `build_top10fh_lookup_by_date(df, trading_dates)` → 逐日表（**仅用单日/短区间**：纸面 ensure 与
  `features/pipeline.py` 的按日路径）；
- 训练 / OOS 评估 / OOS 回测侧 `derive_top10fh_columns(frame, panel)` 走 **`merge_asof`**
  （按 `ts_code` 分组、`ann_ord` 向后匹配）一次性对齐，**不物化逐日表**。

### 6.6 开关与接线（沿 holdertrade/repurchase 先例）

`--enable-top10fh-features`（`walk_forward.py` / `train_ml_model.py`）默认关；**四侧运行时派生**
（训练 / OOS 评估 / OOS 回测 / 纸面），**不写回 cs_train / cs_infer**；启用但未传面板必须报错。
**列集开关（Phase 3 后补，v0.127.2）**：`--top10fh-feature-set {full,concentration}`（**超参签名维度**，
禁止跨取值并组比较）——`full` = 6 值列 + freshness + 哨兵；`concentration` = **单列 `tfh_concentration_chg` + 哨兵**
（依据 Phase 3：家族内仅该列有强信息且正交；**不含 freshness**——`tfh_freshness_days` 与
`fundamental_freshness_days` 实测 ρ=0.999，且本族 freshness 为全市场覆盖、不会被缺失率门禁自动删除，
纳入会把单列对照变成"1 值列 + 1 重复列"）。

## 7. 结论与 Phase 1 硬约束

**PIT 合格 → 可进 Phase 1**（薄接入、默认关、可回退）。Phase 1 必须实现并测试：

1. **单页 6000 + offset 翻页读到空**（`page_limit=6000`；触顶页继续翻，`max_pages` 兜底并告警）；
2. **全字段去重**（跨页实测 0 重复，仍执行）；
3. **禁止使用 `start_date/end_date` 参数**；增量一律按 `period`，
   刷新 = 「最近 2 个已存报告期」∪「区间内**尚无数据**的报告期」（**缺口补齐**，见 §5.1）；
4. 唯一键 = `(ts_code, end_date, ann_date, holder_name)`；同键多行**取 `hold_amount` 最大行**（§4）；
   分析口径"按 `hold_amount` 降序取前 N"；
5. **PIT 锚点 = `ann_date`**（缺失 0%）；按 `ann_date ≤ T` 过滤，同期多版本极罕见（≤0.02%）⇒ 不做版本状态机；
6. 按 `end_date` **年分区**落盘（`data/raw/top10_floatholders/YYYY-12-31.parquet`）；
7. 存储布局与 §5.1 不一致时必须**先改本文件再改代码**。
