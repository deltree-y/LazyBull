# 停牌股票处理指南

## 概述

本指南说明 LazyBull 系统如何处理停牌股票，包括纸面交易和回测两种模式。

## 什么是停牌

**停牌**（Suspension）是指股票因某些原因暂停交易。停牌期间：
- 股票无法买入或卖出
- 价格保持停牌前的水平（不更新）
- 成交量为 0

常见停牌原因：
- 重大事项公告（重组、并购等）
- 临时停牌（异常波动）
- 其他监管要求

## 系统处理机制

### 1. 止损检查

#### 纸面交易
在纸面交易模式下，每日会检查持仓是否触发止损条件。对于停牌股票：

**行为**：
- ✅ 停牌股票会被**跳过止损检查**
- ✅ 不会因停牌期间价格异常触发止损
- ✅ 输出清晰日志："股票 XXX 停牌，跳过止损检查"

**原因**：
- 停牌期间价格数据可能缺失或为 0
- 停牌不代表股票基本面恶化
- 复牌后可根据实际价格重新判断

#### 回测
在回测模式下，止损检查行为与纸面交易一致：

**行为**：
- ✅ 停牌股票跳过止损检查
- ✅ 避免回测结果失真
- ✅ 与实盘行为保持一致

### 2. 调仓/卖出操作

#### 纸面交易

当调仓日需要卖出股票时，系统会检查股票是否可交易：

**停牌情况**：
```
情况：需要卖出 000001.SZ，但该股票停牌
处理：
1. 不生成卖出订单
2. 创建延迟卖出记录（PendingSell）
3. 原因标注为"退出持仓（停牌）"
4. 输出日志："股票 000001.SZ 停牌，无法卖出，加入延迟卖出队列"
```

**无价格数据情况**：
```
情况：需要卖出 000002.SZ，但无法获取价格数据（非停牌）
处理：
1. 不生成卖出订单
2. 创建延迟卖出记录（PendingSell）
3. 原因标注为"退出持仓（无价格数据）"
4. 输出日志："股票 000002.SZ 无卖出价格数据，加入延迟卖出队列"
```

**延迟卖出重试**：
- 系统每日自动检查延迟卖出队列
- 如果股票复牌且有价格数据，自动执行卖出
- 最多重试 N 次（可配置）
- 超过最大重试次数后放弃（需人工介入）

#### 回测

回测中使用类似机制，但通过 `PendingOrderManager` 管理：

**停牌卖出延迟**：
```
情况：T+n 日到期需要卖出，但股票停牌
处理：
1. 不立即卖出
2. 加入延迟订单队列（pending_order_manager）
3. 原因标注为"停牌"
4. 后续交易日自动重试
```

### 3. 日志示例

#### 正常情况
```
[INFO] 止损检查完成：触发 0 个止损信号
[INFO] 纸面交易执行明细（指令模式）- 20260209
[INFO] 卖出: 000001.SZ, 1000股, 原因: 退出持仓
```

#### 停牌情况
```

[WARNING] 股票 000001.SZ 停牌，无法卖出，加入延迟卖出队列
[INFO] 止损检查完成：触发 0 个止损信号
[INFO] 延迟卖出队列：1 只股票待卖出
```

#### 复牌重试
```

```

## 实际案例

### 案例1：持仓停牌，不触发止损

**场景**：
- 持有 600000.SH，买入价 10.00 元
- 设置回撤止损阈值 10%
- 该股票因重大事项停牌，停牌时价格 10.00 元
- 数据系统可能返回 close=0 或 close 缺失

**旧版本行为**（错误）：
- 系统读取 close=0，计算回撤 100%
- 误触发止损信号
- 尝试卖出但因停牌失败

**新版本行为**（正确）：
- 系统检测到 `is_suspended=1`
- 跳过止损检查
- 日志："股票 600000.SH 停牌，跳过止损检查"
- 等待复牌后根据实际价格判断

### 案例2：调仓遇停牌，延迟卖出

**场景**：
- 持有 000001.SZ，1000 股
- 调仓策略决定清仓（目标权重 0%）
- 调仓日该股票停牌

**旧版本行为**（错误）：
- 检测到无卖出价格
- 日志："股票 000001.SZ 无卖出价格数据，跳过卖出"
- **问题**：应卖未卖，且不会重试

**新版本行为**（正确）：
- 检测到无卖出价格
- 判断 `is_suspended=1`
- 创建 PendingSell 记录
- 日志："股票 000001.SZ 停牌，无法卖出，加入延迟卖出队列"
- 每日自动重试，复牌后执行

### 案例3：数据异常与停牌区分

**场景A：数据源异常**
- 持有 000002.SZ
- 调仓日无法获取价格（数据源故障，非停牌）
- 行情数据中 `is_suspended=0`

**处理**：
- 创建 PendingSell，原因："退出持仓（无价格数据）"
- 下一交易日重试获取价格

**场景B：真实停牌**
- 持有 000003.SZ
- 调仓日股票停牌
- 行情数据中 `is_suspended=1`

**处理**：
- 创建 PendingSell，原因："退出持仓（停牌）"
- 复牌后自动执行卖出

虽然系统自动处理延迟卖出，但可以通过以下参数调整行为：

**纸面交易**（在 broker 初始化时可配置）：
```python

# 每次运行自动加载和重试
```

**回测**（在 engine 初始化时配置）：
```python
engine = BacktestEngine(
```

## 最佳实践

### 1. 监控延迟卖出队列

定期检查延迟卖出队列大小：
```python
# 纸面交易
pending_count = len(broker.pending_sells)
if pending_count > 0:
    logger.warning(f"延迟卖出队列：{pending_count} 只股票待卖出")
    for ps in broker.pending_sells:
        logger.info(f"  - {ps.ts_code}: {ps.reason}, 已尝试 {ps.attempts} 次")
```

### 2. 处理长期停牌

对于长期停牌（如重组停牌几个月），建议：
1. 定期查看延迟卖出队列
2. 评估停牌股票基本面
3. 考虑手动干预（如复牌前调整策略）

### 3. 回测验证

使用历史数据回测时：
1. 确保数据包含 `is_suspended` 字段
2. 检查回测日志，确认停牌处理正确
3. 对比不同参数下的延迟卖出效果

### 4. 实盘运行

实盘运行时：
1. 关注每日日志中的停牌提示
2. 复盘时检查延迟卖出执行情况
3. 必要时人工介入处理长期停牌

## 常见问题

### Q1: 停牌期间会错过最佳卖点吗？

**答**：可能会。停牌期间无法交易是A股市场规则，系统行为符合实际交易限制。建议：
- 设置合理的仓位分散度
- 关注持仓公司公告
- 必要时调整策略应对重大事项

### Q2: 延迟卖出最多等多久？

**答**：
- 纸面交易：无明确上限，会持久化到存储中
- 回测：由 `max_retry_days` 参数控制（默认10天）
- 建议：定期清理长期未成交的延迟卖出

### Q3: 停牌股票会影响仓位配置吗？

**答**：会。停牌股票：
- 仍占用仓位（持仓市值按停牌前价格计算）
- 无法卖出释放资金
- 可能导致其他股票买入金额不足

建议在策略层面预留一定现金缓冲。

### Q4: 如何查看停牌股票列表？

**答**：查看延迟卖出队列：
```python
# 纸面交易
for ps in broker.pending_sells:
    if '停牌' in ps.reason:
        print(f"{ps.ts_code}: 停牌中，创建日期 {ps.create_date}")
```

### Q5: 回测与实盘处理停牌是否一致？

**答**：是的。本次修复确保了：
- 止损检查行为一致
- 卖出延迟机制对齐
- 日志提示类似

## 技术实现细节

### 数据字段依赖

系统依赖以下行情数据字段：
- `is_suspended`: 停牌标志（1=停牌，0=正常）
- `close`: 收盘价
- `vol`: 成交量（备用判断停牌）
- `is_limit_down`: 跌停标志

### 模块复用

停牌处理复用以下现有模块：
- `src/lazybull/common/trade_status.py`: 提供 `is_suspended()`, `is_tradeable()` 函数
- `src/lazybull/paper/models.py`: `PendingSell` 数据模型
- `src/lazybull/execution/pending_order.py`: 延迟订单管理器
