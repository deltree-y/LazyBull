# Classification 模型评估指标指南

## 概述

本指南说明在使用 LazyBull 训练分类模型（`--task classification`）时，应重点关注哪些评估指标，以及如何正确解读这些指标。

**关键原则**：分类模型的评估应贴近实际交易场景，重点关注**排序能力**和**TopK 收益**，而不是过度解读传统分类指标（如 Accuracy、Recall）。

---

## 一、推荐关注的指标（按重要性排序）

### 1. 逐日 RankIC（Spearman）⭐⭐⭐⭐⭐

**定义**：每个交易日内，预测概率与真实收益的 Spearman 秩相关系数，再对所有交易日取均值。

**重要性**：**最重要的指标**，直接衡量模型的排序能力。

**计算方式**：
1. 对每个 `trade_date`，计算该日所有股票的预测概率与真实收益的 Spearman 相关
2. 对所有交易日的 RankIC 取均值、标准差
3. 计算 IR（Information Ratio）= RankIC 均值 / RankIC 标准差

**口径一致性**：
- 训练脚本中的逐日 RankIC **与回测 eval panel 的 RankIC 计算口径一致**
- 都是"先逐日计算，再取均值"（而非全样本一次性计算）

**评判标准**：
- **RankIC 均值 > 0.03**：模型有一定预测能力
- **RankIC 均值 > 0.05**：模型有较好的排序能力
- **RankIC IR > 1.0**：RankIC 稳定性较好
- **RankIC IR > 1.5**：RankIC 稳定性很好

**输出示例**：
```
逐日 RankIC 均值: 0.0523
逐日 RankIC 标准差: 0.0412
逐日 RankIC IR: 1.2694
```

### 2. TopK 平均收益（跨日）⭐⭐⭐⭐⭐

**定义**：每个交易日内，按预测概率排序，计算 TopK（K=30/100/300）对应的真实收益均值，再对所有交易日取均值。

**重要性**：**最贴近实际交易的指标**，直接反映策略的盈利能力。

**计算方式**：
1. 对每个 `trade_date`，按预测概率降序排序
2. 取 Top K 只股票，计算其真实收益（如 `y_ret_20`）的均值
3. 对所有交易日的 TopK 收益取均值、标准差

**评判标准**：
- **Top30 收益 > 0.02**（2%）：策略有一定超额收益
- **Top100 收益 > 0.015**（1.5%）：策略有较好的超额收益
- **Top300 收益 > 0.01**（1%）：策略有稳定的超额收益

**输出示例**：
```
Top30 平均收益（跨日）: 均值=0.0234, 标准差=0.0156
Top100 平均收益（跨日）: 均值=0.0189, 标准差=0.0123
Top300 平均收益（跨日）: 均值=0.0145, 标准差=0.0098
```

### 3. AUC（ROC 曲线下面积）⭐⭐⭐

**定义**：二分类模型的 ROC 曲线下面积，衡量模型区分正负类的能力。

**重要性**：**辅助指标**，主要用于快速判断模型是否有区分能力。

**评判标准**：
- **AUC > 0.6**：模型有一定区分能力
- **AUC > 0.65**：模型有较好的区分能力
- **AUC > 0.7**：模型有很好的区分能力

**注意事项**：
- AUC 仅反映"是否能区分正负类"，不直接反映"排序能力"或"收益"
- 在极度不平衡的数据集上（如 pos_topk=300，负类远多于正类），AUC 可能虚高
- 建议结合 RankIC 和 TopK 收益综合判断

### 4. Accuracy / Precision / Recall ⚠️

**重要性**：**不推荐过度解读**

**原因**：
1. **不反映排序能力**：Accuracy 只关心"分对了多少"，不关心"排序是否正确"
2. **不反映收益**：即使 Accuracy=0.9，如果排序错误（把低收益股票排在前面），策略仍会亏损
3. **对阈值敏感**：Precision/Recall 依赖分类阈值（默认 0.5），但实际交易中我们只关心 TopK，不关心阈值

**何时参考**：
- 仅作为辅助指标，快速判断模型是否完全失效（如 Accuracy < 0.5 时可能有问题）
- 不应作为主要优化目标

## 三、常见问题与解答

### Q1: 为什么 Accuracy 很高（0.9+），但回测收益很低？

**A**: Accuracy 只关心"分对了多少"，不关心"排序是否正确"。

**举例**：
- 假设每日有 1000 只股票，pos_topk=100（正类 100，负类 900）
- 模型把所有股票预测为负类：Accuracy = 0.9（900/1000），但完全无法选股
- 模型把低收益股票排在前面：Accuracy 可能很高，但 TopK 收益为负

**建议**：重点关注 RankIC 和 TopK 收益，不要被 Accuracy 误导。

### Q2: 为什么 RankIC 很高，但 AUC 不高？

**A**: RankIC 和 AUC 衡量的是不同维度：
- **RankIC**：衡量排序能力（Spearman 相关）
- **AUC**：衡量区分能力（ROC 曲线）

在极度不平衡的数据集上，即使排序能力很好（RankIC 高），区分能力可能一般（AUC 中等）。这是正常的，不需要过度优化 AUC。

### Q3: TopK 收益为负数，是否说明模型失效？

**A**: 不一定。需要检查：
1. **时间窗口**：验证集是否覆盖了市场下跌期？可能所有股票都是负收益
2. **标签列**：是否使用了正确的原始收益列（如 `y_ret_20`）？
3. **RankIC**：如果 RankIC 仍为正，说明模型仍有排序能力，只是市场整体收益为负

**建议**：结合 RankIC 综合判断。

### Q4: 如何优化分类模型？

**优化目标**：
1. **首要目标**：提高逐日 RankIC 均值和 IR
2. **次要目标**：提高 TopK 收益（特别是 Top30/100）
3. **辅助目标**：提高 AUC

**优化方法**：
- **特征工程**：增加更多有效特征（如价值因子、资金流因子）
- **超参数调优**：调整 `n_estimators`、`max_depth`、`learning_rate`
- **样本权重**：调整 `scale_pos_weight`（默认自动计算）
- **标签定义**：调整 `pos_topk` 或 `pos_quantile`（更窄的正类可能提高精度，但降低召回）

## 四、最佳实践

### 1. 分类任务训练命令推荐

```bash
# 推荐配置：pos_topk=300，使用 y_ret_20 作为标签
python scripts/train_ml_model.py \
    --start-date 20230101 --end-date 20231231 \
    --task classification \
    --pos-topk 300 \
    --label y_ret_20 \
    --n-estimators 200 \
    --max-depth 8 \
    --learning-rate 0.05
```

### 2. 评估指标查看顺序

训练完成后，按以下顺序查看指标：

1. **逐日 RankIC**（首要关注）
   - 均值 > 0.03？
   - IR > 1.0？
   
2. **TopK 收益**（次要关注）
   - Top30 收益 > 0.02？
   - Top100 收益 > 0.015？
   
3. **AUC**（辅助判断）
   - AUC > 0.6？
   
4. **Accuracy/Precision/Recall**（快速浏览即可）

### 3. 与回测结果对比

训练完成后，运行回测验证：

```bash
python scripts/run_ml_backtest.py \
    --start-date 20240101 --end-date 20240630 \
    --model-version <新版本号> \
    --top-n 30
```

**对比**：
- 回测的 RankIC 是否与训练验证集的逐日 RankIC 接近？
- 回测的年化收益是否与 TopK 收益趋势一致？

**注意**：
- 回测结果可能略低于训练验证集（因为有交易成本、停牌、涨跌停等真实约束）
- 如果回测结果大幅低于训练验证集，可能存在过拟合或数据泄漏问题

## 五、总结

分类模型评估的核心原则：

1. **重点关注**：逐日 RankIC、TopK 收益
2. **辅助参考**：AUC
3. **快速浏览**：Accuracy/Precision/Recall（不要过度解读）
4. **口径一致**：训练验证集的逐日 RankIC 与回测 RankIC 计算口径一致
5. **贴近交易**：TopK 收益评估基于原始收益列，更符合实际交易场景

**记住**：分类任务的最终目标是"选出收益最高的 TopK 只股票"，而不是"把所有股票分类正确"。因此，排序能力（RankIC）和 TopK 收益才是真正重要的指标。
