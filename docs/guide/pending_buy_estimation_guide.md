# 补位买入股数估算说明

## 概述

本文档说明补位买入（pending_buys）的股数估算逻辑，确保提示信息与实际执行口径一致。

## 背景

在纸面交易系统中，当买入失败时（如涨停、停牌等），系统会生成补位计划（pending_buys），在下一交易日尝试买入。从 v0.4.2 开始，系统在生成补位计划时显示的"估算股数"与实际执行时的计算逻辑完全一致。

## 计算逻辑

### 统一的估算方法

补位买入股数的计算遵循以下步骤：

```python
# 1. 计算总可用现金（扣除保留比例）
total_cash = account.cash * (1 - pendding_capital_retention_ratio)

# 2. 平均分配到每个补位目标
available_cash = total_cash / total_pending_count

# 3. 根据目标权重计算买入金额
target_value = total_cash * target_weight

# 4. 预估成本（佣金 + 滑点）
estimated_cost = cost_model.calculate_buy_cost(target_value)

# 5. 检查是否超出可用现金
if target_value + estimated_cost > available_cash:
    target_value = available_cash - estimated_cost
    if target_value <= 0:
        return 0  # 现金不足

# 6. 计算股数（按100股取整）
buy_shares = floor(target_value / price / 100) * 100
```

### 关键参数说明

1. **现金保留比例 (`pendding_capital_retention_ratio`)**
   - 默认值：0.3（30%）
   - 配置位置：`configs/base.yaml` 中的 `costs.pendding_capital_retention_ratio`
   - 作用：避免过度买入导致后续无法补位

2. **可用现金分配**
   - 每个补位目标平均分配可用现金
   - 公式：`available_cash = total_cash / total_pending_count`
   - 目的：确保所有补位目标有均等的买入机会

3. **成本预估**
   - 包含佣金和滑点
   - 佣金费率：默认 0.03%，最低5元
   - 滑点：默认 0.05%
   - 总成本 ≈ target_value * 0.13%

4. **100股取整**
   - A股交易单位为100股（1手）
   - 不足100股时，估算股数为0

## 提示信息

### 生成补位计划时的提示

当系统生成补位计划时，会显示如下信息：

```
================================================================================
补位买入目标详情（需要在下一交易日继续买入）
================================================================================
注意：以下股数为估算值，基于当前价格与现金（保留比例 30.0%）
实际执行时会受到执行日价格变化、补位队列长度变化等因素影响，但计算规则一致
================================================================================
股票代码        股票名称      方向     参考价格      估算股数  原因
--------------------------------------------------------------------------------
000001.SZ      平安银行      买入       12.50          3500    补位-跌停
600519.SH      贵州茅台      买入     1850.00           100    补位-停牌
000002.SZ      万科A         买入        8.20      0 (不足一手)  补位-涨停
================================================================================
```

### 说明要点

1. **"估算值"标识**：明确说明这是估算，不是确定值
2. **保留比例提示**：显示当前使用的现金保留比例
3. **影响因素说明**：列出可能导致实际值与估算值不同的因素
4. **不足一手标记**：当估算股数为0时，显示"0 (不足一手)"

## 影响估算准确性的因素

虽然计算逻辑一致，但以下因素可能导致实际执行与估算有差异：

### 1. 价格变化
- **估算时**：使用生成补位计划当日的收盘价
- **执行时**：使用实际执行日的买入价（开盘价或收盘价）
- **影响**：价格变化会直接影响能买入的股数

**示例**：
```
估算时价格：10.00元，估算股数：3500股
执行时价格：11.00元，实际股数：3200股（因价格上涨，股数减少）
```

### 2. 补位队列长度变化
- **估算时**：基于当前补位队列的长度计算
- **执行时**：可能有新的失败买入加入队列
- **影响**：队列变长会导致每个目标分配的现金减少

**示例**：
```
估算时：5个补位目标，每个分配 70,000元
执行时：7个补位目标（新增2个），每个分配 50,000元
```

### 3. 账户现金变化
- **估算时**：基于当前账户现金
- **执行时**：可能有其他操作（如卖出）影响现金
- **影响**：现金增加会使估算偏保守，现金减少会导致买入失败

### 4. 成本预估误差
- 成本预估使用固定费率，实际成本可能略有不同
- 影响较小，通常在1%以内

## 典型场景示例

### 场景1：正常补位

**条件**：
- 账户现金：500,000元
- 保留比例：30%
- 补位目标：5个
- 某股票目标权重：10%
- 股票价格：10元

**计算过程**：
```
total_cash = 500000 * (1 - 0.3) = 350,000元
available_cash = 350000 / 5 = 70,000元
target_value = 350000 * 0.1 = 35,000元
estimated_cost = 35000 * 0.0013 ≈ 45.5元
target_value + cost = 35,045.5元 < 70,000元 ✓
buy_shares = floor(35000 / 10 / 100) * 100 = 3,500股
```

**结果**：估算股数 3,500股

### 场景2：现金受限

**条件**：
- 账户现金：100,000元
- 保留比例：30%
- 补位目标：2个
- 某股票目标权重：50%
- 股票价格：10元

**计算过程**：
```
total_cash = 100000 * (1 - 0.3) = 70,000元
available_cash = 70000 / 2 = 35,000元
target_value = 70000 * 0.5 = 35,000元
estimated_cost = 35000 * 0.0013 ≈ 45.5元
target_value + cost = 35,045.5元 > 35,000元 ✗ (超出限制)
调整：target_value = 35000 - 45.5 = 34,954.5元
buy_shares = floor(34954.5 / 10 / 100) * 100 = 3,400股
```

**结果**：估算股数 3,400股（因现金受限而调整）

### 场景3：不足一手

**条件**：
- 账户现金：5,000元
- 保留比例：30%
- 补位目标：10个
- 某股票目标权重：10%
- 股票价格：100元（高价股）

**计算过程**：
```
total_cash = 5000 * (1 - 0.3) = 3,500元
available_cash = 3500 / 10 = 350元
target_value = 3500 * 0.1 = 350元
estimated_cost = 5元（最低佣金）
target_value + cost = 355元 > 350元 ✗
调整：target_value = 350 - 5 = 345元
buy_shares = floor(345 / 100 / 100) * 100 = 0股
```

**结果**：估算股数 0股（不足一手），显示为"0 (不足一手)"

## 配置调整

### 修改保留比例

若需要调整现金保留比例，编辑 `configs/base.yaml`：

```yaml
costs:
  # 补位买入时保留的资金比例
  # 默认30%，可根据实际情况调整
  # 较高的保留比例：更保守，为后续补位预留更多现金
  # 较低的保留比例：更激进，当前补位使用更多现金
  pendding_capital_retention_ratio: 0.3
```

**建议值**：
- 保守策略：0.3 - 0.5（30% - 50%）
- 平衡策略：0.2 - 0.3（20% - 30%）
- 激进策略：0.1 - 0.2（10% - 20%）

### 修改成本费率

若需要调整成本预估，编辑 `configs/base.yaml`：

```yaml
costs:
  commission_rate: 0.0003  # 佣金费率（双向）
  min_commission: 5.0      # 最小佣金（元）
  slippage: 0.0005         # 滑点比率
```
