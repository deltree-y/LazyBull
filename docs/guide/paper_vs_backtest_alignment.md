# 纸面交易与回测引擎行为对齐说明

## 一手可买约束的差异

### 纸面交易（v0.3.5+）

**等权模式下**，在 T0 生成信号阶段就会：
1. 使用 `MLSignal.generate_ranked()` 获取完整排序候选
2. 检查每只股票按等权分配的资金是否能买至少1手（100股）
3. 不足1手的股票被跳过，从候选中顺延选择下一只
4. 最终保存到 pending 的目标都是可买至少1手的股票

**实现位置：** `PaperTradingRunner._generate_equal_weight_with_lot_constraint()`

### 回测引擎

回测引擎在 T+1 日执行买入时：
1. 根据可交易性过滤（停牌/涨停/ST等）并从候选回填
2. 买入时按整手计算：`shares = int(target_value / trade_price / 100) * 100`
3. **如果计算结果为0股，仍会尝试买入但实际不会成交**

**实现位置：** `BacktestEngine._generate_buy_signals()` 和 `BacktestEngine._execute_buy()`

### 差异分析

| 维度 | 纸面交易 | 回测引擎 |
|------|---------|---------|
| 检查时机 | T0 信号生成时 | T+1 买入执行时 |
| 过滤条件 | 一手可买 + 可交易性 | 仅可交易性 |
| 0股处理 | 提前跳过 | 尝试买入但不成交 |
| 顺延补足 | 是（从排序候选） | 是（从排序候选） |

### 对齐建议

**当前状态：** 纸面交易的约束 **更严格** 于回测引擎

**建议：** 保持现状，原因如下：
1. 纸面交易更接近实盘场景，应该更谨慎
2. 提前过滤可以避免无意义的pending目标和日志噪音
3. 回测引擎的历史数据回测不受影响
4. 如需对齐，建议在回测引擎中也加入一手可买约束（可作为未来优化）

### 验证方法

可通过以下方式验证一致性：
1. 在纸面交易中运行 T0+T1
2. 在回测引擎中回测同一日期
3. 比较最终持仓股票列表（应相同或纸面交易数量≤回测）

## 可交易性过滤的一致性

纸面交易和回测引擎在以下方面保持一致：
- 停牌股票不可买入 ✓
- 涨停股票不可买入 ✓
- ST股票不可买入（通过tradable字段）✓
- 跌停股票不可卖出 ✓

**实现位置：**
- 纸面交易：`PaperBroker._check_can_buy()` 和 `_check_can_sell()`
- 回测引擎：`BacktestEngine._filter_signal_by_tradability()`
