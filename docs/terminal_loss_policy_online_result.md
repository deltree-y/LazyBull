# terminal_loss 暴露政策「在线现算」（P2-5）验证记录

> 版本：v0.127.4 ｜ 日期：2026-09-19
> 关联：R-004 §8/§9（影子实测 + 回撤侧总扫描）、`docs/plans/drawdown_side_sweep_prereg.md`（预登记）
> 结论：**在线现算（S1 语义）成为回测引擎的政策入口**；与冻结系数表臂的差异**可度量、方向混合、量级落在噪声带内**，
> 系数表退化为可选缓存/导出（不再需要人工导出）。

---

## 1. 背景：为什么不再用系数表

系数表（`日期, 暴露系数` 两列 CSV）把「政策」变成了**与某一份持仓路径绑定的离线产物**：

1. λ_t 依赖持仓（组合市值、个股风险分），换任何会改变持仓的配置（Top-N、调仓周期、成本、止损开关…）
   都必须重新导出，否则表与路径不一致；
2. 表把"未来"写进了历史文件，无法回答"实盘今天该用什么系数"；
3. 表的正确性没有自证机制（只能人工比对），而在线现算可以与离线实现**共用同一套公式**并逐值自证。

因此 P2-5 把 λ_t 改为**逐日现算**：`λ_t = f(折模型, 当日持仓, 当日截面)`；
系数表保留为**缓存/回放**格式（`--exposure-table`），与在线口径互斥。

## 2. 实现与语义

| 项 | 口径 |
|---|---|
| 实现位置 | `src/lazybull/risk/terminal_loss/exposure_online.py`（唯一实现来源） |
| 复用的离线实现 | 折模型映射（`load_fold_index` + `select_fold_for_date`）、打分输入装配（`_attach_inputs`）、事后标签（`build_terminal_loss_labels`）、日级聚合与判定（`build_daily_frame` + `apply_rolling_gate` / `calibrate_gate`+`apply_gate`）——**禁止任何公式复制** |
| **引擎语义 S1** | λ_t 用**判定时点持仓**（当日执行前），与"买入预算 × **信号日** λ"契约一致 |
| 同日单次评估 | T0 判定与 T+1（按信号日取 λ）共用首次结果（provider 缓存）；未命中的日期当场评估 |
| 未成熟日 | **仍在面板**（离线台账含全部日；丢掉会让滚动窗口缺日、阈值不同），成熟后按 `valid` 过滤非法行 |
| 缺口日 | 无持仓/无计划日不评估 ⇒ 消费侧沿用最近一次有效 λ（与离线导出 `ffill` 对齐） |
| 覆盖生效（`--policy-coverage-start`） | **只抑制动作、不抑制历史**：生效日之前的交易日仍照常打分/入面板/累积滚动阈值，但 λ 恒返回 1.0；被抑制的触发日计入 `pre_coverage_trigger_days` |
| 默认关闭 | 无政策源时 `set_exposure_policy` 未调用 ⇒ 引擎**逐位一致**（测试锁定） |
| 互斥 | `--exposure-policy` 与 `--exposure-table` 同时给出直接报错 |

## 3. 计算成本实测（真实数据，2024 年截面）

| 环节 | 实测 |
|---|---|
| 交易日历加载 | 0.03 s |
| `clean/daily` 30 日窗口加载 | 0.15 s |
| σ 面板（`compute_sigma_daily_panel`） | 0.10 s |
| 当日截面装配 + 打分 | 0.02 s |
| 特征矩阵装配 + 推理 | <0.01 s |
| **合计** | **≈0.26 s/日**（首日含面板构建，后续日仅增量） |

结论：在线现算的额外成本对回测（数千交易日）在分钟级，可忽略；无需为了性能保留 CSV 通路。

## 4. 正确性验证

### 4.1 自证：离线回放 vs 冻结表（同一持仓台账）

用 `replay_lambda_series(provider, snapshot_files, ...)` 在**收盘后持仓**口径下回放，
与 R-004 冻结表 `exposure_table_combined_rolling_250d.csv` 逐日比对（466 日）：

| 结果 | 日数 | 说明 |
|---|---|---|
| 一致 | **463** | — |
| 未回放（快照缺该日） | 2 | `20240611` / `20250612`，表值均为 1.0（非触发日，回放默认 1.0 ⇒ 无影响） |
| λ 不同 | 1 | `20250211`（表 1.0 / 在线 0.5）：标签成熟时点导致的窗口内标签组成差异（**已登记为已知差异**，见 §5） |

回放覆盖 834 日（2022-07-01 ~ 2025-12-12）：判定 662 日、触发 **137** 日（表 90 日 λ<1 / 回放 91 日，
多出的 1 日即 `20250211`）、无持仓跳过 109 日、窗口不足跳过 60 日、非法标签剔除 14 行。

修复过程中的两项对齐（均已落测试）：

1. **缺口日顺延**：无持仓日不评估 ⇒ 消费侧沿用最近一次 λ，与离线导出 `ffill` 语义一致（缺少该语义会产生 10 日差异）；
2. **逐股标签子集**：成熟判定只对该日持仓股票取标签，避免用"全截面标签集"判断成熟（会产生跨股票口径漂移）。

### 4.2 引擎实跑（S1）vs 冻结表：λ 层面

窗口（2024-01-02 ~ 2025-12-04）共 466 日，与冻结表逐日比对：

| 结果 | 日数（N1 全区间臂） | 日数（N2 同覆盖臂） |
|---|---|---|
| 一致 | **439** | **441** |
| 未覆盖（在线臂当日无持仓/窗口不足 ⇒ 无消费者） | 20 | 20 |
| λ 翻转 | **7**（4 日表 1.0 / 在线 0.5，3 日表 0.5 / 在线 1.0） | **5**（2 日表 1.0 / 在线 0.5，3 日反之） |

N2 的 5 日差异列表：`20240119`、`20240621`、`20250211`、`20251030`、`20251121`（均为孤立单日，非成块）。
（N2 是修正 `--policy-coverage-start` 冷启动语义后的产物；修正前该臂为 35 日差异、集中在 2024-01，见 §4.4。）

翻转率 **1.6%**、方向**混合**。**注意含两层分量**：

1. **纯语义差**（判定时点 vs 收盘后持仓）——由 §4.1 同路径自证给出：**1/466 日**；
2. **路径分叉**——在线臂若不加 `--policy-coverage-start`，从 **2023-04-26 起**就已生效
   （实测 1630 日序列 / 153 个触发日：2023 年 62、2024 年 48、2025 年 43；**窗口外 66 日**），
   进入窗口时的持仓/现金已与冻结表臂不同 ⇒ 后续 λ 序列必然继续分叉。

因此“7 日”不能读作实现差异；**同路径自证的 1/466 才是实现同源的证据**。

### 4.3 引擎实跑（S1）vs 冻结表：净值层面

窗口 2024-01-02 ~ 2025-12-04（与 R-004 §9 同窗口、同基线 A0），四臂同表比较
（工具：`scripts/analyze_drawdown_sweep.py`，口径与 §9 一致）：

| 臂 | 累计收益 | Δ收益 | ΔCAGR | MaxDD | ΔMaxDD | ΔSharpe | 减仓（笔/金额） | 信号期内（λ<1）pp | 信号期外（λ=1）pp |
|---|---|---|---|---|---|---|---|---|---|
| A0 基线 | 0.3325 | — | — | −26.95% | — | 0.609 | 0 / 0 | — | — |
| A1 冻结表（§9 登记臂） | 0.5055 | **+17.30pp** | +7.58pp | −25.93% | **+1.02pp** | 0.985 | 156 / 384.1 万 | 3.37 | 7.14 |
| N1 在线（全区间，2022-07 起） | 0.4941 | +16.17pp | +7.10pp | −27.12% | **−0.17pp** | 0.958 | 121 / 292.1 万 | 1.84 | 8.01 |
| N2 在线（同覆盖 `--policy-coverage-start 20240102`） | 0.4671 | +13.46pp | +5.94pp | −27.10% | **−0.15pp** | 0.908 | 138 / 336.3 万 | 1.51 | 6.57 |

**结论（必须如实登记）**：

1. **崩盘月贡献逐值可复现**：N2 与 A1 的按月归因在 **2024-01（+6.00pp）与 2024-02（+4.04pp）完全相同**
   ⇒ 在线实现没有“失效”，与离线实现同源；
2. **但主判据（ΔMaxDD）不可复现**：同覆盖下 N2 = **−0.15pp** vs A1 = +1.02pp。
   差异只能归因于 **5/446 日 λ 翻转（1.1%）**改写的 2024-06/07 路径：它抬高了 A1 进入 9 月的净值水平，
   而各臂谷底同为 **2024-09-18**（链式回撤由峰-谷结构决定）；
3. **收益维度与 §8/§9 登记一致**：日差以**信号期外**（λ=1 日）为主（6.57~8.01pp / 合计 8.08~9.84pp，
   占 81%~87%）⇒ 再次印证「收益主要为滞留行为收益、**不可外推**」；
4. **稳健性含义（新登记）**：ΔMaxDD 在 §9 被称为“低噪声主判据”，本次实测显示它**对 λ 序列 1% 量级的扰动即可翻转符号**
   （5 日 λ 变化 ⇒ ±1.2pp）⇒ 该主判据的适用范围必须限定为**同一 λ 序列内**的比较（换种子/换表的对比），
   **不得**外推为“实现无关”或用于跨实现（离线表 vs 引擎在线）结论互换。

**操作结论**：暴露政策作为**可选引擎能力**保留（默认关）；
**不得**以“回撤改善”为由启用（在线口径不达标），仅可作为回撤侧的可选手段并需逐次复核。

### 4.4 已发现的缺陷与修复（端到端验证的直接收益）

| 缺陷 | 症状 | 修复 |
|---|---|---|
| 执行侧残留 `exposure_table is None` 判定 | 在线政策源（表为 `None`）下 **减仓单被静默丢弃**：判定 154 日、生成卖单 176 笔、**成交 0 笔** | `exposure_trim.py::_execute_pending_exposure_trims` 改用 `_has_exposure_source()`；新增回归测试 `test_online_provider_trim_orders_do_execute`（判定 → T+1 执行 → `risk_trim` 成交 + 释放额累计） |
| `--policy-coverage-start` 冷启动陷阱 | 早期实现“生效日之前直接返回 1.0 且不评估” ⇒ 面板无行、滚动阈值从生效日重算 ⇒ **生效初期数十个交易日永不触发**（实测使 2024-01 整月失效：与冻结表 35 日差异、方向高度集中） | 改为**只抑制动作、不抑制历史**（照常打分/入面板/成熟），被抑制触发日计入 `pre_coverage_trigger_days`；新增回归测试 `test_provider_coverage_start_suppresses_action_but_keeps_history`（含“被抑制日必须仍在面板内”断言） |

两个缺陷都属**只在在线通路出现**的静默失效（冻结表通路不受影响），因此**不影响 R-004 §8/§9 的任何登记值**；
二者都是端到端实跑（而非单元测试）发现的——这也是 P2-5 必得做完整批次复核的理由。

## 5. 已知差异与代价（必须随结论一并报告）

1. **S1 与离线台账不逐位相等**：判定时点持仓（当日执行前）≠ 离线收盘后持仓。**同路径**自证实测 **1/466 日**差异
   （`20250211`）；**不同路径**（引擎实跑 vs 冻结表臂）为 7/446 日、方向混合。净值影响见 §4.3。**不得**声称两者等价。
2. **在线覆盖范围 = 各折 ES 区间（2022-07 起）**，比 R-004 总扫描窗口（2024-01 起）更宽：
   窗口外也会动作，因此"窗口外逐位一致"这一判据**对在线臂不适用**（冻结表只覆盖窗口）。
   需要与冻结表严格同覆盖时用 `--policy-coverage-start`。
3. `20250211` 单日差异（自证模式）：来自标签成熟时点差异，登记为已知差异，未做进一步追因（量级 1/466 日，且属回放模式）。
4. 政策层自身的边际收益口径不变：R-004 §9 的扫描结论（回撤维度保留、收益维度不可外推）**不因本实现而改变**；
   在线现算是**工程实现替换**，不是新的收益来源。

## 6. 使用方式

### 6.1 命令行（单次实验）

```bash
python scripts/walk_forward.py ... \
  --exposure-policy "arm=combined,mode=rolling,window=250,regime_q=0.6667,score_q=0.5,lambda=0.5" \
  --policy-model-root data/walk_forward/terminal_risk_wf \
  --policy-arm-suffix _d5_v6m_fscore \
  [--policy-coverage-start 20240102]
```

- `--exposure-replenish`（对称回补）、`--exposure-trim-tolerance 0.03` 仍按原语义生效；
- 与 `--exposure-table` **互斥**。

### 6.2 批量（`scripts/batch/batch_walk_forward.ps1`：所有参数统一在该脚本配置）

```powershell
$policy_model_root     = "data\walk_forward\terminal_risk_wf"
$policy_arm_suffix     = "_d5_v6m_fscore"
$policy_coverage_start = ""     # 留空 = 各折 ES 全区间，与冻结表同覆盖时填窗口起点（如 20240102）

$exposure_arm_list = @(
    # 默认臂 = 登记基准臂（E2-滚动250 / λ=0.5 / 在线现算 / 不裁剪覆盖）
    # Name: 臂名（拼进 batch-period-label）；Policy/Table 互斥；Tolerance=0 表示引擎默认 3%
    [PSCustomObject]@{ Name = "e2online"; Policy = "arm=combined,mode=rolling,window=250,regime_q=0.6667,score_q=0.5,lambda=0.5";
                       Table = ""; Replenish = $false; Tolerance = 0; StopLoss = $false }
    # 基线对照（不启用政策）时换成下面这一臂：
    #[PSCustomObject]@{ Name = "neutral"; Policy = ""; Table = ""; Replenish = $false; Tolerance = 0; StopLoss = $false }
)
```

臂名会拼进 `--batch-period-label` 与任务日志（便于按臂检索产物）；
给出任一暴露命令行参数即退化为“单臂覆盖”（忽略清单，不叠加）。
**不默认 λ=0.3 / 回补 / 止损**的依据见 §4.3 与 R-004 §9（避免把已登记的“滞留行为收益”当成更优参数）。
