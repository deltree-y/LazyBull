## 1. 诊断问题与口径

**问题**：2012 前主要因子列覆盖率是被「0.6 缺失率门禁」拖死（可工程解 ⇒ 立项变列集
训练），还是 TuShare 源头无数据（硬约束 ⇒ 不立项）？

口径（与生产语义逐项对齐，括号内为证据）：
- 采样日 = 2005Q1~2011Q4 各季末交易日（28 个）+ 20120104 锚点；截面 = 当日 raw/daily 全量
  ts_code（1,257@2005Q2 → 2,212@2011Q4）。
- 日分区数据集覆盖率 = 当日分区命中截面比例；历史类（季/年分区）覆盖率 = 截面中存在
  PIT 记录（`ann_date ≤ T`）的比例——因子查询表前向填充语义，有记录即可用
  （`factors/fundamental.py` 等 lookup 同口径）。
- 特例逐一对齐生产代码：report_rc 的 PIT 列 = `report_date`（无 ann_date 列，
  `factors/consensus.py:207`）；fund_portfolio 股票代码列 = `symbol`（ts_code 为基金代码，
  `factors/fund_portfolio.py:69`）；lhb_* 个股级稀疏事件**未上榜 0 填充**（
  `factor_handlers.py:397 LhbFactorHandler` docstring「个股级稀疏，未上榜填 0」）⇒
  列恒非 NaN，事件稀疏性不构成门禁问题；top_list/block_trade 按 20 交易日事件窗计
  覆盖（lhb_ 20 日 / block_discount 10 日滚动聚合语义）。
- 衍生列（量价/风控/市场状态/标签）= daily 驱动 ⇒ 100%（250 日长窗 4 列须 daily
  历史 ≥250 交易日 ⇒ 20060110 起）；zscore/neu 随母列。
- 门禁仿真：列年均覆盖率 ≥40% ⇒「0.6 门禁幸存」（训练入口
  `max_feature_missing_ratio=0.6`，`ml/train_core/prepare.py:94`）；现役模型列集 =
  `data/models/stock_selection/v24288_features.json`（154 列）。

## 4. 判定与建议（待用户裁决）

**剖面结论：瓶颈不是门禁拖死，也不是源头硬缺失——2007 起主要因子列 86% 幸存。**

- 2007~2011 段可用列集 = 132~134/154（85.7~87.0%），剔除的 20~22 列（north/cyq/margin）
  全部硬缺席，按变列集口径在早期列集中自然剔除即可（manifest `available_from` 治理对象）。
- 2005~2006 段受 moneyflow 源（2007 起）+ forecast/express 覆盖爬坡拖累（幸存 67.5~79.9%）
  ⇒ **建议样本起点 = 2007，不取 2005**。
- 可挽回样本估算：2007~2011 ≈ 1,215 交易日 × 均 ~1,700 股 ≈ **210 万股票-日**，相对
  现样本（2012~2026，11,032,382 股票-日）增量 ≈ **+19%**（> M1.5 停止规则 15% 阈值）；
  regime 多样性显著（2007 泡沫 / 2008 崩盘 / 2009 修复 / 2010-11 震荡 = 4 类独立 regime）。
- **建议：立项「分时段变列集训练」（起点 2007）**——判据 §8.1-M1.5 全部满足
  （瓶颈非硬约束、增量 >15%）。成本按 M1.5 登记：编码 2~3 单元 + 重训 1 批（1.5~2h，需授权）。
  **裁决点**：立项与否属项目方向决策，提交用户裁决（本报告即 M1.5 前置诊断产物）。

## 5. 附带发现：manifest available_from 回填的语义冲突（登记）

冻结文档 §4 预定「单元 5 剖面报告回填精化 manifest available_from」。但 store 层
`load_features` 将 available_from 实现为**硬查询屏障**（query.start_date < available_from
⇒ ValueError，`data_store.py:514-520`）——若按剖面写入（如 north_* = 20141117），
全区间（20120104 起）加载这些列将直接报错，**会破坏既有闸门/对账通路的全列加载**。
处置：available_from 剖面值先落本报告与 JSON 产物（`col_available_from` 字段）作治理输入；
**manifest 写入推迟到 M1.5 立项实施**——届时需先裁决 available_from 的语义
（训练列集元数据 vs 加载屏障），再设计写入路径（防「治理元数据反过来破坏数据通路」）。

## 6. 口径 caveat 登记

- lhb_*：零填充语义下恒非 NaN（幸存），但 2007 前事件稀疏（20 日窗命中 31.5%→16.2%）
  ——信号内容稀薄属真实世界状态，不是可用性问题；
- forecast/express 覆盖爬坡为 TuShare 源真实状态（2005 预告覆盖 23% → 2009 快报 39%）；
- margin 族 2010-03 前两融业务不存在（世界状态，非数据缺失）；
- 剖面为源级覆盖度量，未逐列重算因子值——派生列的「源覆盖 ⇒ 列可用」假设对
  rolling/EMA 族成立（daily 驱动），对多源列取 min（保守）。
