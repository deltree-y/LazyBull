# 纸面交易买入失败补位机制实现

## PR 标题

实现纸面交易买入失败时的候选顺延补位与 T2 继续买入机制

## 版本更新

- 版本号：0.3.5 → 0.3.6
- 类型：功能增强

## 背景与问题

### 当前问题

在当前的纸面交易系统中，当 T1 执行买入时若遇到不可买入情况（如涨停、停牌、不可交易），系统仅记录 warning 日志并跳过该股票，导致以下问题：

1. **资金闲置**：买入失败后，原本计划用于该股票的资金长期闲置，降低资金使用效率
2. **持仓不足**：无法达到目标持仓数量（top_k），影响策略执行效果
3. **与回测不一致**：回测系统具有"候选顺延"能力，而纸面交易缺乏类似机制

### 用户需求

当 T1 执行买入时，若有目标因不可买入未成交，系统应：
1. 基于 T1 当日数据重新选择 top_k（k=未买入数量）的补位股票
2. 生成 T2 继续买入计划，并清晰提示用户
3. 若 T2 仍有不可买入，需继续补位，最多递归/重试 5 次
4. 补位股票必须满足"一手可买"约束（至少 100 股）

## 实现方案

### 1. 数据模型设计

#### PendingBuy 模型

新增 `PendingBuy` 数据类，与现有的 `PendingSell` 对称：

```python
@dataclass
class PendingBuy:
    """延迟买入订单（补位计划）"""
    ts_code: str  # 股票代码
    target_weight: float  # 目标权重
    reason: str  # 原因（如：补位-涨停）
    create_date: str  # 创建日期 YYYYMMDD
    attempts: int = 0  # 尝试次数
    last_attempt_date: str = ""  # 最后一次尝试日期（用于避免同日重复推进）
    original_signal_date: str = ""  # 原始信号日期（T0日期）
```

#### 持久化支持

在 `PaperStorage` 类中新增：
- `save_pending_buys(pending_buys: List[PendingBuy])`: 保存补位队列到 JSON 文件
- `load_pending_buys() -> List[PendingBuy]`: 从 JSON 文件加载补位队列

存储路径：`./data/paper/pending_buys/pending_buys.json`

### 2. 买入失败检测与记录

#### PaperBroker.generate_orders() 改进

在生成订单过程中，增强买入失败的检测和记录逻辑：

```python
failed_buy_targets = []  # 记录买入失败的目标

# 检查各种失败情况
if not can_buy:
    failed_buy_targets.append(TargetWeight(..., reason=f"{reason}（{buy_reason}）"))
    continue

# 现金不足
if buy_value + estimated_cost > available_cash:
    failed_buy_targets.append(TargetWeight(..., reason=f"{reason}（现金不足）"))
    continue

# 不足一手
if buy_shares < 100:
    failed_buy_targets.append(TargetWeight(..., reason=f"{reason}（不足一手）"))
    continue
```

失败原因包括：
- 无价格数据
- 涨停
- 停牌
- 不可交易（ST/上市不足等）
- 现金不足
- 不足一手（价格过高，无法买入 100 股）

### 3. 补位目标生成

#### PaperTradingRunner.generate_replacement_targets()

新增方法用于生成补位目标，核心逻辑：

1. **复用现有信号链路**：使用 `MLSignal` 和 `_generate_equal_weight_with_lot_constraint()` 方法
2. **排除已持仓股票**：补位只考虑新股票，不重复买入已持仓标的
3. **应用一手约束**：确保每个补位目标至少能买入 100 股（1 手）
4. **等权分配**：对补位股票使用等权分配，基于剩余可用现金计算
5. **候选顺延**：从排序候选列表中按序选择，直到满足数量要求或候选耗尽

#### 输出格式

补位目标输出表格与 T0 输出保持一致：

```
============================================================================
补位买入目标详情（需要在下一交易日继续买入）
============================================================================
股票代码         股票名称     方向      参考价格      建议股数      原因
----------------------------------------------------------------------------
000001.SZ       平安银行     买入       10.50          9500     补位-信号生成
000002.SZ       万科A       买入        8.20         12100     补位-信号生成
============================================================================
```

### 4. 补位重试机制

#### PaperBroker.retry_pending_buys()

新增方法处理补位队列的重试，类似 `retry_pending_sells()`：

1. **加载补位队列**：从持久化文件加载 `pending_buys`
2. **检查可交易性**：逐个检查是否可以买入
3. **尝试次数管理**：
   - 不同日期：`attempts += 1`，更新 `last_attempt_date`
   - 同一日期：不增加 `attempts`（避免重复推进）
4. **最大尝试次数**：默认 5 次，超过则移除订单
5. **执行买入**：可交易时生成订单并执行
6. **更新队列**：保存剩余的补位订单

#### 纸面交易工作流集成

在 `paper_trade.py run` 命令中新增步骤 3：

```python
# 步骤3: 处理延迟买入队列（补位计划）
pending_buy_actions = _process_pending_buys(runner, corrected_date, config)
```

每日运行时自动处理补位重试，无需手工执行额外命令。

### 5. T1 执行后自动生成补位计划

#### _execute_t1_if_pending() 改进

在 T1 执行完成后，检查是否有买入失败：

```python
# 获取买入失败的目标
failed_buy_targets = runner.broker.get_failed_buy_targets()

if failed_buy_targets:
    # 获取下一交易日
    next_trade_date = runner._get_next_trade_date(trade_date)
    
    # 生成补位目标
    replacement_targets = runner.generate_replacement_targets(
        trade_date=trade_date,
        failed_count=len(failed_buy_targets),
        ...
    )
    
    # 转换为 PendingBuy 并加入队列
    for target in replacement_targets:
        pending_buy = PendingBuy(...)
        runner.broker.pending_buys.append(pending_buy)
    
    # 保存补位队列
    runner.broker.storage.save_pending_buys(runner.broker.pending_buys)
```

### 6. 递归补位流程

补位机制支持递归重试，最多 5 次：

```
T1 买入失败（涨停）
  └─> 生成 T2 补位计划 (attempts=1)
        └─> T2 仍失败（涨停）
              └─> 保留在队列 (attempts=2)
                    └─> T3 重试...
                          └─> 最多到 attempts=5，然后移除
```

每次重试时，如果仍失败，订单会保留在队列中，继续在下一交易日重试。

## 纸面交易与回测的一致性分析

### 一致点

1. **候选顺延逻辑**：
   - 纸面交易：通过 `generate_replacement_targets()` 实现
   - 回测：通过 `_generate_equal_weight_with_lot_constraint()` 实现
   - 两者都复用 `MLSignal.generate_ranked()` 获取排序候选

2. **一手可买约束**：
   - 两者都应用相同的约束：至少能买入 100 股（1 手）
   - 不足一手的股票会被跳过，继续顺延选择下一只

3. **信号生成源**：
   - 都使用相同的 `MLSignal` 和特征数据
   - 都应用相同的股票池过滤和成交额过滤

4. **等权分配**：
   - 都使用等权分配计算目标权重

### 不可避免的差异

1. **时点差异**：
   - **纸面交易**：T1 买入失败后，使用 T1 当日数据生成 T2 补位目标
   - **回测**：在 T0 信号日就已经获取完整排序候选，直接顺延
   - **原因**：回测有"上帝视角"，可以提前知道所有候选；纸面交易必须在 T1 才能发现买入失败

2. **信号新鲜度**：
   - **纸面交易**：补位使用 T1 当日最新特征数据
   - **回测**：使用 T0 信号日的特征数据
   - **影响**：纸面交易的补位可能因市场变化选择不同的股票

3. **现金计算基准**：
   - **纸面交易**：补位时使用"剩余可用现金"计算
   - **回测**：使用总资产*权重计算
   - **原因**：纸面交易中，部分资金可能已经用于其他买入

4. **递归深度**：
   - **纸面交易**：最多 5 次递归重试
   - **回测**：可能一次性顺延更多候选
   - **影响**：极端情况下，纸面交易可能无法完全填满目标持仓

### 差异的合理性

这些差异是**合理且不可避免**的，原因：

1. **真实约束**：纸面交易必须遵循真实交易的时间顺序，无法提前知道未来
2. **动态调整**：使用最新数据生成补位目标，更符合实盘操作逻辑
3. **风控需要**：5 次重试上限避免过度追逐失败目标

## 验收标准

- [x] 当 T1 遇到涨停/停牌等导致买入失败时，不简单放弃
- [x] 系统生成下一交易日的补位买入计划，输出与 T0 相同格式的表格
- [x] 连续多日失败会继续补位重试，最多 5 次，然后停止并清晰提示
- [x] 补位逻辑应用"一手可买"约束（至少100股）
- [x] 新增测试覆盖"买入失败触发补位并生成下一交易日计划"的核心逻辑
- [x] PR 描述说明纸面交易与回测的一致性与差异

## 注意事项

1. **不引入历史兼容分支**：直接使用新格式，旧数据会自动适配（空列表）
2. **日志级别**：补位相关的重要信息使用 `logger.info()`，便于用户观察
3. **幂等性保障**：T1 的执行记录中增加 `failed_buys_count` 字段
4. **同日保护**：通过 `last_attempt_date` 避免同日多次推进 attempts

## 后续优化方向

1. **更智能的补位策略**：考虑市场情绪、个股强度等因素
2. **补位优先级**：优先重试涨停股票（可能第二天开板）
3. **部分成交支持**：如果只能买入部分股数，允许部分成交
4. **补位报告**：生成补位成功率、平均重试次数等统计报告
