# 指令驱动 T0→T1 执行模式

## 版本信息
- **PR 版本**: v0.3.12
- **修改日期**: 2026-02-09
- **修改类型**: 功能增强

## 问题描述

### 现状问题
在之前的实现中，T0 阶段生成信号并打印"建议股数"，但 T1 阶段仍然基于 `target_weight` 和 `current_weight` 的比较来决定是否生成订单。这导致以下问题：

1. **不一致性**：T0 显示"减仓 100 股"，但 T1 由于权重重新计算和整手取整，实际可能不执行减仓
2. **用户困惑**：用户根据 T0 提示手工操作，期望 T1 也按相同逻辑执行，但实际可能不一致
3. **典型案例**：603115.SH 在 T0 建议卖出 100 股，但 T1 实际无减仓成交

### 根本原因
- T0 的"建议股数"仅用于展示，不参与 T1 的实际决策
- T1 重新基于总资产、目标权重计算股数，导致与 T0 计算结果不一致
- 整手取整（100 股）在 T0 和 T1 两次计算，可能产生不同结果

## 解决方案

### 设计原则
1. **指令驱动**：T0 生成明确的交易指令（包含具体股数），T1 优先执行指令，不再重新计算
2. **幂等性**：同样的指令在 T1 执行时，除非有外部约束（现金不足、停牌等），必须产生一致的结果
3. **向下兼容**：保留旧的 pending_weights 机制，T1 优先读取指令，如无指令则回退到旧模式
4. **复用能力**：最大程度复用现有的 Order/Fill/执行逻辑、pending_buys/pending_sells 队列

### 实现方案

#### 1. 数据模型扩展

新增 `TradeInstruction` 数据类（`src/lazybull/paper/models.py`）：

```python
@dataclass
class TradeInstruction:
    """交易指令 - T0 生成的明确交易指令"""
    ts_code: str  # 股票代码
    action: str  # 操作类型：buy/sell
    shares: int  # 交易股数（已整手取整）
    price_type: str  # 价格类型：open/close
    reason: str  # 交易原因
    source_date: str  # 源日期（T0日期）YYYYMMDD
    target_weight: float = 0.0  # 目标权重（可选）
    original_signal_date: str = ""  # 原始信号日期（可选）
```

#### 2. 存储层扩展

在 `PaperStorage` 类（`src/lazybull/paper/storage.py`）中新增：

- **存储路径**：`data/paper/instructions/YYYYMMDD.parquet`
- **保存方法**：`save_instructions(trade_date, instructions)`
- **读取方法**：`load_instructions(trade_date)`

#### 3. T0 工作流修改

在 `PaperTradingRunner.run_t0()` 方法中：

1. 生成 targets（保持不变）
2. **新增**：调用 `_generate_instructions()` 从 targets 生成明确指令
   - 基于当前持仓和目标权重计算每个标的的操作（买入/卖出/加仓/减仓）
   - 计算具体股数并整手取整
   - 标注价格类型（buy_price_type / sell_price_type）
3. 持久化指令到 T1 日期
4. **兼容性**：同时保存 pending_weights（旧模式）

#### 4. T1 工作流修改

在 `PaperTradingRunner.run_t1()` 方法中：

1. **优先**读取交易指令（新模式）
2. 如无指令，读取 pending_weights（旧模式）
3. 如有指令，调用 `broker.execute_instructions()` 执行
4. 如无指令但有 pending_weights，调用 `broker.generate_orders()` 执行（旧逻辑）

#### 5. 经纪层执行方法

在 `PaperBroker` 类（`src/lazybull/paper/broker.py`）中新增 `execute_instructions()` 方法：

**卖出处理**：
- 检查可交易性（停牌、跌停等）
- 如不可卖出，加入 `pending_sells` 队列
- 如可卖出，按指令股数执行（不超过实际持仓）

**买入处理**：
- 检查可交易性（停牌、涨停等）
- 如不可买入，加入补位计划（`pending_buys`）
- 如现金不足：
  - 缩比买入到最大整手
  - 如不足 1 手，加入补位计划
- 如可买入，按指令股数执行

```
TradeInstruction:

  - action: buy/sell
  - shares: 股数（整手）
  - price_type: open/close
  - reason: 原因
  - source_date: T0日期
  - target_weight: 目标权重（可选）

```

### 兼容性
- **旧数据**：现有的 `data/paper/pending/YYYYMMDD.parquet` 文件继续有效
- **新数据**：优先使用 `data/paper/instructions/YYYYMMDD.parquet`
- **降级**：如无指令文件，自动回退到旧模式（基于 pending_weights）

## 如何验证

### 单元测试
运行测试用例验证核心功能：
```bash
pytest tests/test_paper_trading.py -v -k instruction
```

### 集成测试
1. **T0 生成指令**：
   ```bash
   python scripts/paper_trade.py run --trade-date 20260121 --mode t0
   ```
   验证：`data/paper/instructions/20260122.parquet` 文件已生成

2. **T1 执行指令**：
   ```bash
   python scripts/paper_trade.py run --trade-date 20260122 --mode t1
   ```
   验证：
   - 日志显示"读取到 N 条交易指令（新模式）"
   - 对每条指令都生成了对应的成交记录
   - 减仓/清仓指令必须产生卖出成交

3. **验收场景**：
   - T0 对持仓标的输出"减仓 100 股"
   - T1 当天该标的可卖出
   - T1 必须生成 sell 100 的订单并成交
   - 持仓股数减少 100

### 边缘情况验证
1. **现金不足**：
   - T0 生成多个买入指令，总金额超过账户现金
   - T1 执行时应缩比买入，不足 1 手的加入 pending_buys

2. **不可交易**：
   - T0 生成卖出指令，T1 当天该股票跌停
   - T1 应将指令加入 pending_sells 队列

3. **补位机制**：
   - 买入失败的标的应进入补位计划
   - 后续交易日通过重新生成信号进行补位

## 注意事项

### 使用建议
1. **新项目**：直接使用新模式，T0 自动生成指令
2. **旧项目迁移**：
   - 首次运行新版本时，T0 会同时生成指令和 pending_weights
   - T1 会优先使用指令，向后兼容
3. **数据清理**：旧的 pending_weights 文件可保留，不影响新模式

### 已知限制
1. **历史数据**：旧版本生成的 pending_weights 文件不会自动转换为指令
2. **手工调整**：如需手工修改指令，直接编辑 parquet 文件（不推荐）
3. **价格类型**：指令中的 price_type 必须与 T1 配置一致，否则可能有偏差

### 风险提示
1. **整手约束**：所有指令股数已整手取整，实际执行不会偏离
2. **现金管理**：买入指令总额可能超过现金，系统会自动缩比或延迟
3. **可交易性**：不可交易的指令会延迟执行，不会强制成交

## 后续优化方向

1. **指令可视化**：在 T0 结果中展示生成的指令详情
2. **指令校验**：T1 执行前校验指令合法性（股数、价格等）
3. **指令修正**：支持手工修正指令（如调整股数、取消指令）
4. **历史指令**：记录历史指令执行情况，便于回溯分析
5. **性能优化**：大量指令时的批量处理优化
